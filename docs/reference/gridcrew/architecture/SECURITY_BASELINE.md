# GridCrew 安全基线

本文件冻结安全边界与分阶段要求，不声明尚未实现的控制已经上线。

## 身份、授权与租户隔离

- IAM 将人类、DigitalEmployee、Service Identity 和外部系统身份映射为可审计主体。
- API 在入口认证并执行租户、组织、工作区和数据范围授权；Workflow 在命令与 Activity 边界校验授权上下文；Tool Gateway 在每次外部调用前再次校验 AccessRole、PermissionPolicy、风险与审批。
- Temporal Client、Worker 与 Namespace 均采用最小权限、独立凭据和允许的 Task Queue；Worker 不接受跨租户越权命令。
- PostgreSQL 使用 `tenant_id` 强制查询范围，并在 M6 前落地行级或等效防绕过隔离策略。
- 对象存储使用按租户划分的 Bucket 或 Key 前缀，服务端验证前缀，禁止客户端任意指定路径。

## 数据、网络与密钥

- 传输使用 TLS；持久化数据按部署环境使用静态加密与密钥轮换策略。
- Secret Manager 是生产密钥的边界；`.env.example` 仅包含占位变量，真实 `.env`、密钥、证书和 Token 不入仓。
- 日志、Trace、Prompt、回执和 Evidence 元数据必须最小化采集并脱敏；Evidence 原件按访问策略受控。
- Connector 默认禁止任意网络出口；按域名、IP、端口和协议白名单放行，并记录请求目的地。
- Tool Gateway 使用工具白名单与参数 Schema 校验；高风险动作要求服务端风险判断和审批。

## AI 与审计风险

- 对 Prompt Injection、工具注入、越权指令和回执伪造进行来源标记、上下文隔离、参数约束和人工审批设计。
- 审计日志采用追加写语义，定义保留、导出和访问审批；审计事件不得被业务调用覆盖。
- 软件供应链需在 M0 建立依赖锁定、许可证检查与 SBOM 计划；不得以未审计依赖承载生产控制。
- 非生产环境不得使用未经脱敏的客户数据；测试样本应可追溯且可清理。
- 生产控制、调度下发和其他高风险动作永久保持服务端授权、审批、证据和人工接管边界。

## 分阶段落地

| 里程碑 | 必须落地的安全事项 |
|---|---|
| M0 | `.env.example`、密钥不入仓、基础身份与配置边界、结构化日志脱敏约定、依赖许可证与 SBOM 计划。 |
| M1 | API 身份认证、最小权限服务身份、租户上下文、Gateway 调用校验和基础审计。 |
| M6 | RBAC+ABAC 强制执行、数据隔离验证、审批审计保留导出、Connector 白名单和高风险生产控制。 |
