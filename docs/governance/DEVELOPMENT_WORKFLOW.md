# Development Workflow

## Milestone 执行循环

1. 产品/架构负责人批准并单独下发一个 Milestone；
2. Codex 读取 `AGENTS.md`、当前任务、Accepted ADR、上阶段报告和工作树；
3. 将需求追踪矩阵更新为本阶段实施计划；
4. 先改领域与契约，再改 Adapter、API、Worker 和前端；
5. 同步迁移、权限、审计、错误、可观测性、SDK 和文档；
6. 执行单元、架构、契约、集成、Workflow、E2E、安全与故障测试；
7. 对照质量门禁和追踪矩阵复核；
8. 输出执行回报并停止，不自动进入下一阶段。

## 变更控制

- 需求不清：新增 `OPEN_QUESTIONS.md` 条目；
- 核心语义变化：先 Proposed ADR，批准后实施；
- 公共契约变化：说明兼容窗口、迁移、SDK 和事件影响；
- 数据变化：新增迁移及升级/回滚验证，不改历史迁移；
- 外部依赖：记录版本、许可证、安全、用途和替代方案；
- 用户已有修改：保留并避让，无法避让时停止请求决策。

## 完成定义

“完成”必须同时意味着真实代码、真实运行结果、测试证据、迁移、文档、需求状态和执行报告一致。Mock、静态 UI、固定 JSON、未执行测试或外部依赖待接入不得报告为完成。

## 分支与提交

M-1 不规定远程平台和分支模型。M0 应结合团队规模决定 trunk-based 或短分支策略。在 Git 身份、代码所有者和评审人未确认前，不得伪造提交或启用强制保护规则。
