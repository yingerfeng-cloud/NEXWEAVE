# NEXWEAVE 前端全量 UI/UX 审查与整改报告

日期：2026-09-10  
范围：M9-FE；桌面 Web；主导航全量页面及 Chronos-2 Living Knowledge 视图  
状态：实施、独立审查、本地技术验收完成；停止于 M9-FE

## 1. 结论

本轮已对工作台、知识建模、知识治理、智能使用、系统五组菜单下的全部页面进行页面元素、色彩、排版布局、用户体验和交互审查，并完成整改。整改保持既有 API、权限、状态机、Evidence、Release 不可变和页面 URL 语义不变；没有新增数据库迁移、后端接口、依赖或外部资源。

整体视觉继续采用 NEXWEAVE 深色赛博朋克基线：深黑底、紫色层级、青色主操作、荧光绿成功态、琥珀/红色风险态。页面统一使用 AppShell、PageHeader、Panel、StatusPill、EmptyState、ErrorState、TechnicalDetails 等设计系统组件，保留必要的技术身份和原始值，但不再把实现代码直接当作主界面文案。

## 3. 主要不合理设计与整改

| 编号 | 审查发现 | 整改结果 |
| --- | --- | --- |
| F1 | 列表、卡片和筛选器直接暴露大量大写状态码、密级码和实现词，用户难以判断下一步动作。 | 扩充统一状态字典和语义色调；主界面显示中文状态，原始值留在 `TechnicalDetails`、标题或辅助信息中。资料、空间、任务、审核、发布、Living Knowledge 等页面统一处理。 |
| F2 | 各页面错误表现不一致，有的只有一行文本，有的没有可重试入口。 | 统一 `ErrorState`、页面错误横幅和 AppErrorBoundary；请求失败提供明确的“重试”，渲染失败提供“刷新”，并保留服务端错误语义。 |
| F3 | 未选择知识空间、空间为空或无权限时，页面仍展示可提交表单，容易造成无效操作。 | 增加 no-space guard、EmptyState 和“返回空间/重新选择”动作；轮询、加载、提交均在缺少空间时停止。 |
| F4 | 版本号、Schema key、标签、主张和 Wiki 标题过长时挤压列宽或破坏布局。 | 对生命周期值、Studio key/version、标签、Wiki 标题、主张文本增加省略/换行/两行截断；主张页改为更合理的宽窄栏比例，保证桌面阅读宽度。 |
| F5 | 测试/隔离/失败演练空间和领域包曾在常规列表中出现，容易被误认为生产对象。 | 默认隐藏 test、stage-a、isolated、failure、synthetic、technical-pilot 等 fixture；仅本地开发者模式可查看。P-101 等演示数据仍显式标注“合成数据/未经现场核实”，不冒充工业证据。 |
| F6 | 表单按钮未始终声明类型，重复点击可能重复提交；导航后快速导航结果可能残留。 | 所有非提交按钮显式 `type="button"`；加载、同步、发布、关注、回滚等动作增加 busy/duplicate guard 和进行中反馈；Cmd/Ctrl+K 快速导航在打开、选择、导航后清空状态。 |
| F7 | 知识图谱节点过小且集中，标签难读，视图缺少空间层次。 | 提高默认缩放、节点半径和标签字号，调整力导向排斥/中心力、边距和边界钳制；在桌面画布内获得更均衡的可读性。 |
| F8 | 平台管理筛选后标题仍显示总数，筛选条件跨 Tab 残留，用户无法确认当前范围。 | 标题改为当前可见数量；切换 Tab 重置筛选与错误状态；弹窗和列表的错误/空状态一致。 |
| F9 | 资料筛选、空间成员角色/密级下拉暴露英文枚举，和中文界面不一致。 | 选项显示中文（公开/内部/机密/高度受限；管理员/编辑者/审核者/查看者等），提交值保持原 API 枚举，不改变契约。 |
| F10 | Living Knowledge 绑定、比较和帮助文案不够明确，用户容易把导入或合成数据当成现场预测。 | 增加“合成数据 · 非现场观测”“导入数据 · 未经核实”、只读/差异说明和质量中文描述；保留 Chronos-2、Observed、Forecast 等领域语义身份以便追溯。 |

## 4. 设计系统与实现要点

- `apps/web/src/design-system/ui.tsx`：统一 Modal 可访问名称、状态映射、错误重试和基础反馈组件。
- `apps/web/src/design-system/AppShell.tsx`：统一品牌、空间选择器、主导航、系统导航、快速导航、身份和退出交互；导航动作均显式按钮语义。
- `apps/web/src/styles/tokens.css`、`foundation.css`、`components.css`、`core-structure.css`、`shell.css`、`source-center.css`、`knowledge-surfaces.css`：统一颜色、间距、边框、圆角、排版、响应式桌面布局、长文本策略和图谱可读性。
- 页面级整理覆盖 `OverviewPage`、`SpacesPage`、`SourceCenter`、`TaskCenter`、`CompileCenter`、`SchemaStudio`、`PackCenter`、`WikiWorkbench`、`WikiLinkGraph`、`ReviewCenter`、`M7Knowledge`、`IntegrationCenter`、`AdminPage`、`LivingKnowledge`、`BindingWizard` 及 `App` 路由壳层。
- 桌面 Web 是本轮目标；未扩展移动端专用布局，也没有引入新 UI 依赖。

## 6. 迁移、安全与证据边界

- 无新增或修改数据库迁移；无 API、事件、权限、路由或领域对象语义变更。
- 无新增依赖、远程字体、图片或第三方脚本；既有权限和服务端门禁继续有效，前端未绕过 Release、Evidence 或不可变规则。
- 原始 ID、校验和、状态码及模型/提供商技术身份仅在需要追溯的位置保留；主界面不将其误作用户任务文案。
- 测试、合成、技术试点和 P-101 演示数据未被表述为真实工业效果、专家批准或正式验收。

- M9-FE 的设计系统统一、全路由对齐、交互状态、桌面浏览器核验和本地技术验收均已完成。

- M9 专家阈值、真实评审/发布记录和工业验收仍属于独立治理事项，本轮前端整改不关闭、不冒充这些事项。
