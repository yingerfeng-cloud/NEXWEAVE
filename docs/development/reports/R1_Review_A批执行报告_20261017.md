## 升级、配置与回退

1. 备份当前数据库并保留审计/不可变发布数据。使用项目配置机制更新运行镜像，`alembic upgrade head` 新增 `0012_r1_review`。迁移不补造过去的审阅版本，不改历史迁移。
2. 旧的未结束审核没有可证明的快照，操作返回 `REVIEW_VERSION_REQUIRED`；有资格的起案人调用 `POST /review-cases/{id}/restart` 并填写理由，绑定当前服务端版本，重走所有阶段。已完成审核不重新绑定。
3. 旧的未发布候选缺少冻结 `entity_snapshots` 时需新建；历史已发布 Release 仍读取原快照。旧内容存在性评估不能满足新的 `r1-query-v2` 发布质量门禁，需重新执行。
4. 有效成员 clearance 现在封顶全局 clearance。按真实业务职责配置 knowledge_engineer/reviewer/publisher；管理员不自动具备每个阶段资格。不得通过同一人兼任来规避 HIGH 最终独立性。
5. 新投递恢复由 API lifespan 执行，使用现有数据库与 Temporal 配置；多 API 实例通过行锁/SKIP LOCKED 竞争。没有新增 secret、队列或外部服务。生产仍禁止 dev/session，OIDC Web 流程待 B；不可为启动方便开放生产开发登录。
6. 安全依赖版本、许可证与替代方案见 DEPENDENCY_BASELINE；Debian/Alpine 使用官方签名仓库，安全包精确锁定。后续仓库版本退役需正常更新锁定，不回退已知有漏洞版本。
7. 回退前停止新版本 API/worker、导出本批审核版本及投递证据；未完成投递先恢复或明确处置。`alembic downgrade 0011_m95a` 删除两个新增表及触发器，会失去新增版本绑定记录；历史 Claim、Release 与审核动作保留。随后恢复兼容旧应用。回退会重新暴露旧缺陷，仅在受控修复窗口采用。
