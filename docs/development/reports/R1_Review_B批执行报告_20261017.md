## 实现与变更文件

- `ReviewOperations.tsx`、`ReviewEvidenceView.tsx`、`review_repository.py`：显式策略与起案，服务端正文、支持/反对/背景证据、原文定位、实际版本差异、作者/编辑者/起案人/各阶段人员/终审人，带实质理由的阶段动作。冲突双方并排核对，CONDITIONAL 必填条件，裁决历史与当前阻断等级一致。
- `QualityReleaseForms.tsx`、`release_repository.py`：多题版本化问题集、可维护预期答案/Claim/拒答原因、显式 Schema/套件/模型/Prompt 与三类发布成员；逐题显示实际召回、答案、引用、拒答和评分。候选、套件和评估详情复用当前依赖门禁；受限结果仅元数据，不冒用历史分数。
- `release_manifest.py`：冻结所选内容来源的实体版本，避免后续未选编译指针带入额外来源；Wiki 主实体/来源上下文明示进入清单，背景锚点不冒充已批准 Claim Evidence。
- `auth_routes.py`、`web_auth.py`、`identity.py`、`LoginPage.tsx`、`App.tsx`、Settings/Compose：OIDC Authorization Code + PKCE S256、浏览器绑定、一次性 Redis state、nonce/issuer/audience/signature/at_hash/实际身份校验，短期 Bearer 会话、过期/401 清理，生产继续禁用开发登录。worker 跟随生产 OIDC 身份配置，不获得 Web client secret。
- 空间变化卸载旧详情，异步任务/编译/审核/评估/连接器同步显示实际终态；连接器明确“保存配置（不测试连接）”。图谱从受门禁保护的冻结实体名选择起点。
- 浏览器发现并修复：用户创建表单错误默认 issuer；非空 Relation 响应缺失有效期字段导致发布页500；职责分离409被误译成“刷新重试”；TXT 末尾换行导致末段丢失/空文档；Wiki 要求批准却没有批准入口。初始 Temporal 连接失败也规范为可重投的依赖错误，拒绝审核的审计与被回滚动作分开保存。

## 迁移、配置与回退

`0013_r1_wiki` 只拓宽审核目标约束，Wiki批准事实保存在其权威版本对应的 APPROVED ReviewCase，Wiki行和历史Release保持不可变。没有Wiki个案时可 `alembic downgrade 0012_r1_review`；已有Wiki审核历史时迁移明确拒绝降级，应前滚修复或从升级前备份整体恢复，不能删除审核历史强行回退。

新导入/重新解析默认 builtin/1.0.1；冻结1.0.0仍保留原算法以支持历史任务重放。原始失败解析和Raw记录没有改写。

生产需设置 `.env.example` 所列 OIDC issuer/audience/JWKS、Web授权/Token端点、client id、secret引用环境和固定HTTPS public URL，确保IAM redirect匹配 `/auth/callback`；生产 `NEXWEAVE_LOCAL_DEV_IDENTITY_ENABLED=false`。API/worker配置组合已做合成生产参数校验，未启动生产或访问外部IAM。Web会话不保存离线refresh token，部署可配置IdP登出端点；外部SSO登出效果待联调。

需求追踪：NXW-REVIEW-002、NXW-QUALITY-001/002、NXW-RELEASE-001/002、NXW-NFR-SEC-001、NXW-NFR-AUD-001；F06—F11 与补充运行缺陷。停止边界仍为R1，本批记录后继续已授权C修复，不进入M10。
