- `relation_evidence.py`、本地规则Provider：仅在原文明示端点、方向及肯定关系时生成候选；否定、独立列举、猜测和仅Schema允许的关系不生成。真实文本输出同样检查逐条原文、锚点、对象归属和Schema范围；仍必须人工审核。畸形输出和错把B原文归给A被拒绝。
- `lexical_search.py`、`query_engine.py`、`release_repository.py`：移除当前哈希向量路径；明确词面/属性检索与真实embedding策略。中文、自然问句、实体编号、Schema术语、错误对象及完整原文多实体边界均有回归。Query/Evaluation继续共用检索、证据检查和回答流程。词面回答明确为经审核原文摘录。

## 预测与取消证据

已具备本地固定Chronos-2模型，因此实际运行了4个时间递进起点：512个合成点，前60%起步、history=96、步长24、horizon=12；输入截止点早于评分窗口。Chronos MAE依次0.04638/0.01265/0.09332/0.02153；持久值基线0.05278/0.70694/0.33388/0.52998；10–90覆盖率1/1/0.75/1。逐折分位损失、输入校验和、权重/配置哈希及实际库版本在证据JSON中。小规模合成序列不能代表工业准确率或区间校准。

真实HTTP/Temporal/CPU worker另完成负荷保持/抬升两个Chronos场景及Persistence对照；源/窗口/单位/冻结输入、成功幂等、无未来输入失败及不可变行均有真实运行核对。Profile的8+0/0+8/4+4通过，8+1/8+8拒绝。

取消分别记录，不能合并成一个“全部成功”：

1. 直接真实Chronos入口，在收到MODEL_READY后取消，子进程退出-15。这个入口的数据库/S3为NOT_APPLICABLE。
2. 真实PG/ASGI/RustFS在实际PUT完成后触发取消：数据库0制品，对象精确版本及删除标记均为0。数值Provider和冻结输入是明确替身，非完整Temporal模型链。
3. 真实HTTP/Temporal取消运行：DB为CANCELLED/0制品，S3该run前缀0版本/0标记；Temporal工作流CANCELED有真实取消回执。重试请求、完整context与model_revision相同并成功。关闭历史只见Activity取消请求，未见其确认；同一运行的模型就绪时点未观测，不能据此声称“在数值计算中已完成中断”。

硬崩溃发生在对象PUT后、finally清理前的窗口未演练，也没有新增自动孤儿对象清扫服务。异常清理失败会报告需对账，不能写为清理成功。分位越阈继续不是故障概率，预测继续不作为Evidence、因果、优化或自动执行。
